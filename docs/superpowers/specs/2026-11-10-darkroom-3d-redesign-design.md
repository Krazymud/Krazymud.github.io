# 暗房全站 3D 重构设计

**状态：** 设计已对齐（对话 §1–§4 通过）；待实现计划  
**日期：** 2026-11-10  
**参考：** 抖音「电子底片 / Darkroom」互动礼物视效（modal `7703659502550602681`）  
**工作标题：** 「暗房」（对外不再使用「青庐 / 日课 / 锦匣 / 案头」文案；正式英文名可后续替换，不阻塞实现）

## 1. 目标与非目标

### 目标

- 整站唯一体验为 **全 3D 暗房**：启封后进入可交互桌面（信封、胶卷、灯箱、冲印盘、观片器等）。
- **内容来自现有 vault**（加密 manifest + blobs）；照片按拍摄内容分成若干胶卷；笔记与清单均以「信」呈现，外观区分。
- **在暗房隐喻内完成读写**（加照片、写信、改清单），底层仍用现有 mutate / COS STS 同步。
- **去掉背单词 / 日课** 及词库资源。
- **视效按最佳全 3D 做**；iPhone 等高性能移动端 **不降视效、不做 2.5D 替代壳**。

### 非目标

- 不保留旧青庐信息架构与主导航。
- 不实现 WebGL 失败时的 2.5D 平行产品（仅保留浏览器无法创建 WebGL 时的明确错误/提示页，不换玩法）。
- 不在本设计中重做 COS/SCF 基础设施（沿用现切流）。

## 2. 入口与信息架构

1. **唯一公开入口：** 启封页（解密口令；可选「记住这台设备」）。
2. 口令正确 → 相机推进进入 **主桌面**（3D）。
3. 解锁后无旧站顶栏；次要能力收纳为桌面物件：
   - **锁上** → 回启封
   - **同步口令** → 抽屉/台历类物件（逻辑同现 STS gate）
4. 删除路由与产品面：日课 / trial、词库浏览、旧 Home 叙事页、旧 Settings 主导航文案。

## 3. 3D 场景与交互

### 场景（运镜推进，非多页网站跳转）

| 场景 | 行为 |
|------|------|
| 启封 | 门扉/台面外；口令 UI（HTML overlay） |
| 主桌面 | 信封堆、胶卷区、灯箱、冲印盘、观片器 |
| 信封特写 | 笔记信笺 / 清单信笺翻阅与编辑 |
| 选卷 | 若干胶卷罐陈列；点选进入 |
| 底片条 | 横滑负片 + 放大；点帧看大图 |
| 灯箱 / 冲印盘 | 看帧；新照片「显影」短反馈 |
| 观片器 | 逐帧拨看（首版即交付，与桌面同级视效） |

### 原则

- 点物件进入，明确返回桌面。
- 编辑不回到旧「表单页为主」的 UI；空白信纸 / 单据纸 / 冲印盘即编辑入口。
- 电影感灯光、暗角、轻胶片噪点；尊重 `prefers-reduced-motion` 时减少运镜（切场景），**不**因此换成 2.5D 布局。
- iPhone：同级材质与阴影策略；用分辨率缩放、纹理预算、资源流式加载做工程优化，不降低设计目标。

## 4. Vault 映射与编辑

| Vault | 暗房 |
|-------|------|
| `photos[]` | 胶卷帧 / 灯箱 / 观片器 |
| `notes[]` | 信笺 A：打字机风正文信 |
| `lists[]` | 信笺 B：打孔单据风（可勾选） |
| sync gate | 次要物件 |
| remember / lock | 门扉侧 |

### 分卷（按拍摄内容）

- 解锁后读取每张照片的 `caption`、`date`（及实现期可选用的 thumb 辅助信号）。
- **自动归入 3–5 卷**（不硬凑视频里的四个英文名）；无 caption / 无法归类 → 「未分类」卷，可后再挪。
- 归属持久化：vault 扩展字段（推荐）或独立 rolls 覆盖表，键为 photo `source`；卷名可改。
- **首版卷清单**在实现期首次可解密环境下根据真实 caption 定稿，写入配置并允许人工调整。加密仓库无法在未启封时预分类。

### 编辑隐喻

- 新笔记 → 空白信纸 → `saveNote`
- 新清单 → 单据信纸 → `saveList` / `toggleListItem`
- 新照片 → 冲印盘/装卷 → `addPhoto` + 显影动画
- 删改 → 暗房工具隐喻 → 现有 delete/save API
- 「还没同步」等状态 → 台面纸条，不回到旧 banner 主导布局

## 5. 技术架构

```
启封 (Unlock) → VaultSession
                 ↓
         DarkroomApp (R3F Canvas)
           ├─ SceneGraph (桌面与物件)
           ├─ CameraRig (dolly / 特写)
           ├─ HtmlOverlays (信笺编辑、口令、同步)
           └─ VaultBridge (useVaultMutate / STS / COS)
```

- **渲染：** React Three Fiber + drei；资源 glTF/纹理按场景加载。
- **数据：** 保留 `src/vault/**` 加密与 mutate；UI 层替换为 Darkroom。
- **同步：** 现有 `VITE_COS_*` / STS issuer；暗房不改变 CAM 边界。
- **构建：** 去掉对 `public/words/**` 与 trial 页面的引用；可删除词库文件于实现计划中单列。

### 测试

- Vault 单元/集成测试尽量保留（bridge 不破坏合约）。
- 新增：分卷纯函数测试（caption → roll id）；关键场景挂载 smoke（jsdom 下 mock R3F 或抽非 WebGL 逻辑测）。
- 手动：iPhone Safari 全路径启封 → 选卷 → 读写信/照片 → 同步。

## 6. 删除与迁移清单

**删除或下线**

- 日课 / ECDICT / `public/words/**`（实现计划中删除或停止打包）
- 旧 Home / Trial 路由与文案中的「青庐」品牌对外露出
- 旧 Vault/Settings 作为主壳的页面结构（逻辑迁入暗房物件）

**迁移**

- 现有 vault 数据格式兼容；分卷为附加元数据，不要求用户重新加密整库。
- CDN/Pages 仍发静态站；首包变大需关注 COS 同步与字体策略（与既有 Deploy 问题分开跟踪）。

## 7. 风险

| 风险 | 缓解 |
|------|------|
| 全 3D 工期与包体 | 分里程碑：可启封桌面 → 信/卷可读 → 可写 → 视效抛光 |
| iPhone 热与内存 | 纹理流式、限制同屏高模；不改变「不降视效」目标 |
| caption 贫乏导致分卷弱 | 「未分类」卷 + 可编辑归属表 |
| 编辑 HTML 与 WebGL 焦点/键盘 | 特写时锁定控制器，overlay 可访问 |

## 8. 成功标准

1. 冷启动仅见启封；无日课入口；无「青庐」主导航文案。
2. 启封后进入全 3D 桌面；iPhone 上可达为完整 3D 体验（非 2.5D）。
3. 照片出现在分卷中；笔记/清单为两种信笺且可编辑并写回 vault。
4. 同步口令与 COS 路径在暗房内可用；设备间可见编辑（在既有 STS/CORS/桶配置正确前提下）。
5. `prefers-reduced-motion` 减少运镜但仍留在 3D 场景图内。

## 9. 实现顺序（供后续 plan）

1. 路由与启封壳替换；移除 trial 入口。  
2. R3F 主桌面 + 相机；占位物件。  
3. VaultBridge：读照片/笔记/清单；分卷算法 + 持久化。  
4. 信笺 A/B 读写；冲印盘加照片。  
5. 底片条 / 灯箱 / 观片器抛光；动效与音效（可选）。  
6. 文案去青庐化、删词库、验收 iPhone。

# Midnight Garage 设计文档

日期：2026-10-09
状态：待审阅

## 1. 目标

把 `krazymud.github.io` 从 2018–2019 年的 Hexo 博客，重构成一个送给女朋友的个人站点。站点以黑武士超跑为视觉主题，包含两部分：

- **赛道试炼**：创意背四六级单词，每天 20 词，关卡式答题加间隔复习。
- **保险库**：用口令加密的私人空间，存放真实照片、笔记和清单。

第一版的范围是完整的视觉外壳、完整的背单词流程，以及能放真实内容的加密保险库。

### 完成标准

1. 她在手机上打开网址，能进入车库首页。
2. 能完整跑完一轮 20 词试炼；第二天，到期的复习词会按规则出现。
3. 能导出学习进度，并在另一台设备上导入后继续学习。
4. 输入正确口令能看到真实照片和笔记；公开仓库里只能拿到密文。
5. 低端设备或开启「减少动态效果」时，所有功能照常可用。

### 第一版不做

跨设备自动同步、在网页上编辑保险库内容、单词标注四级或六级、例句、账号系统。

## 2. 视觉方向

- **主题**：夜间私人车库里的一辆哑光黑超跑。不使用任何真实汽车品牌的车标或名称。
- **配色**：
  - 车库和赛道试炼：大面积点缀用牛血红 `#9E1C22`，关键元素（出发按钮、连击数、正确选项、氮气光效）用酒红 `#C1272D`。
  - 保险库：大面积点缀用古铜香槟 `#A8894F`，关键元素（解锁光、选中照片）用暗香槟 `#BF9F62`。
  - 背景是接近纯黑的冷灰（约 `#050506`–`#1F1F22`），正文文字为 `#E4E4E6`，次要文字为 `#86868C`。
- **字体**：中文使用系统字体（苹方、微软雅黑等），不下载中文字体。英文标题和数字使用一款开源（OFL）的方正科技感字体，只截取用到的字符。

## 3. 架构

### 3.1 仓库和部署

- 现有 Hexo 成品整体保存到 `legacy-blog` 分支，然后从 `master` 移除。
- `master` 存放新站源码。GitHub Actions 依次执行：安装依赖 → 运行测试 → 构建 → 把 `index.html` 复制为 `404.html` → 发布到 GitHub Pages。
- 一次性手动操作：在仓库 Settings → Pages 里把来源设为「GitHub Actions」。

### 3.2 技术栈

实施时使用以下工具的最新稳定版：Vite、React、TypeScript、React Router、Tailwind CSS、Motion、React Three Fiber（含 drei 和 postprocessing）、Vitest。

### 3.3 页面和 3D 场景

整站是一个单页应用。一个 3D 画布始终挂在页面底层，切换栏目时不重建，只移动镜头、改变灯光：

| 路由 | 栏目 | 镜头和灯光 |
|---|---|---|
| `/` | 车库 | 聚光灯下缓慢绕车，红色光带扫过车身 |
| `/trial` | 赛道试炼 | 镜头压低到车侧，背景是向前延伸的夜间赛道线 |
| `/vault` | 保险库 | 镜头移到车尾，灯光从红色渐变为香槟金 |

### 3.4 代码模块

每个模块只负责一件事，模块之间通过明确的接口通信：

| 模块 | 职责 | 依赖 |
|---|---|---|
| 外壳 `shell` | 3D 场景、导航、红金主题切换、声音开关、降级判断 | 无 |
| 试炼 `trial` | 每日选词、复习间隔、干扰项挑选（纯函数）；答题界面和结算界面 | 词库数据、进度存储 |
| 进度存储 `progress` | 读写本地进度、版本迁移、导出和导入 | 无 |
| 保险库 `vault` | 口令派生密钥、解密、记住解锁；照片、笔记、清单的展示 | 无 |
| 词库数据 `public/words/` | 静态 JSON 词包 | 由脚本生成 |
| 本地脚本 `scripts/` | 生成词库、加密保险库内容；只在开发者电脑上运行 | Node.js |

站点配置放在 `src/config/site.ts`：她的昵称、在一起的起始日期（可选）。

## 4. 赛道试炼

### 4.1 词库

- 脚本 `scripts/build-words` 读取 ECDICT（MIT 协议），筛出标签含 `cet4` 或 `cet6` 的词条，合并去重。
- 每个词保留：单词、音标、词性、精简后的中文释义（去掉过长或生僻的义项）。
- 新词顺序按常用程度从高到低排列（使用 ECDICT 的词频字段）。
- 输出为每包约 500 词的 JSON 文件，外加一个索引文件，按需加载。

### 4.2 每日选词

- 「一天」从本地时间凌晨 4:00 开始算。
- 每天最多 20 词：先选到期的复习词（越过期越优先），剩余空位按顺序补新词。
- 到期词超过 20 个时，多出的部分顺延到第二天。
- 当天的 20 词一旦生成就固定下来；中途退出后再进入，会从剩下的题继续。

### 4.3 题型和干扰项

- 新词：看英文选中文。
- 复习词：随机出看英文选中文，或看中文选英文。
- 每题四个选项。三个干扰项从词性相同、常用程度相近的词里随机挑选，并且不能与正确答案的释义重复。

### 4.4 答题流程

- **答错**：正确选项亮起，显示音标和释义，约 1.5 秒后自动进入下一题；该词记为「不会」。
- **答对**：转速表指针拉高，背景闪过一段赛道加速；随后出现「还行」和「会了」两个按钮，4 秒内不点则记为「还行」。
- 连击达到 5 和 10 时，各触发一次「氮气」光效。
- 每个单词旁有发音按钮，使用浏览器自带的英语语音朗读。
- 电脑上可以用数字键 1–4 选择选项。

### 4.5 复习间隔

每个词记录当前间隔天数 `interval`（新词为 0）：

- 「不会」：`interval = 1`。
- 「还行」：`interval = max(3, interval × 2)`。
- 「会了」：`interval = max(7, interval × 2)`。
- 下次到期日 = 今天 + `interval`。
- `interval ≥ 30` 的词计为「已掌握」。

### 4.6 结算界面

显示圈速（本轮用时）、正确率、最高连击、本轮新词数和复习词数、已掌握总数，以及明天到期的词数。

### 4.7 进度存储

- 存在浏览器的 `localStorage` 里，数据带 `schemaVersion` 字段，格式升级时自动迁移。
- 每个词的记录：`interval`、`due`（到期日）、`lastResult`、`seenCount`。另外保存当天的题目列表、答题进度和历史统计。
- **导出**：下载一个 JSON 文件。
- **导入**：先校验文件格式和版本，显示文件里的已学词数，确认后覆盖当前进度。

## 5. 保险库

### 5.1 内容来源

- 本地文件夹 `vault-src/`（已加入 `.gitignore`，绝不提交），包含 `photos/`、`notes/`（Markdown）、`lists/`，以及一个 `manifest` 文件，记录每项内容的标题、日期和显示顺序。
- 运行 `scripts/encrypt-vault` 时，在终端交互输入口令。口令不能通过命令行参数或环境变量传入，也不会写进任何文件。
- 口令必须至少 16 个字符，或至少 4 个以空格分隔的词，否则脚本拒绝执行。

### 5.2 加密流程

1. 照片：缩放到最长边 2000 像素，转为 WebP；另外生成缩略图；抹掉全部 EXIF 和元数据（包括 GPS）。
2. 生成随机的 256 位内容密钥（DEK）。
3. 每个文件（照片、缩略图、笔记、清单、内容清单）分别用 AES-256-GCM 加密，每个文件使用独立的随机 IV。
4. 用 PBKDF2-SHA256（600,000 次迭代、随机盐）从口令派生出包装密钥（KEK），再用 KEK 以 AES-GCM 加密 DEK。
5. 输出到 `public/vault/`：
   - `vault.json`：盐、迭代次数、加密后的 DEK、加密后的内容清单。
   - 若干密文文件，文件名是随机字符串，不包含任何原始信息。
6. 统计输出总大小，超过 300 MB 时发出警告。
7. 更换口令时，只需重新包装 DEK，不必重新加密所有文件。

公开仓库能看到的只有：密文文件的数量和大致大小。

### 5.3 解锁和展示

- 输入口令，按住「一键启动」按钮：引擎声响起，香槟金光扫过，柜门打开。
- 口令错误（AES-GCM 校验失败）时，界面抖动并提示「口令不对」。
- 解锁后先解密内容清单和缩略图；点开某张照片时才解密原图。离开保险库时，释放所有解密出来的临时对象。
- 「在这台设备上记住」：把 DEK 以不可导出的 `CryptoKey` 形式存进 IndexedDB，不保存口令。「锁上」按钮会清除它。不勾选时，DEK 只存在内存里。
- 展示方式：照片是车展灯箱式网格，点开后全屏浏览；笔记是带日期的卡片；清单显示每项的勾选状态。第一版保险库只读。

## 6. 车库首页、动效和性能

### 6.1 首页内容

- 3D 超跑作为主角。
- 用她昵称的问候语。
- 今日试炼状态：已完成数 / 20、到期复习数、出发按钮。
- 保险库入口。
- 如果配置了起始日期，显示「在一起第 N 天」。

### 6.2 3D 和动效

- 模型：CC0 或 CC-BY 授权的通用超跑模型，用 Draco 或 meshopt 压缩到 3 MB 以内。重新上材质：哑光黑车身，牛血红卡钳和腰线。CC-BY 模型在页脚署名。
- 环境：暗调摄影棚 HDRI（CC0），带微弱倒影的地面，周期性扫过车身的光带。
- 后期效果：辉光、暗角、轻微胶片颗粒；氮气光效触发时短暂加入色散。
- 开场：首次访问时，加载进度显示为一块逐渐转满的转速表，车灯亮起后进入车库。之后再访问直接进入车库。
- 声音：点火、引擎轰鸣和解锁音效使用 CC0 素材，只在用户点击之后播放。右上角有静音开关，状态保存在本地。

### 6.3 性能和降级

- 首屏脚本（不含 3D）压缩后约 200 KB 以内；3D 场景在界面渲染之后再异步加载。
- 帧率下降时，自动降低渲染分辨率，并关闭部分后期效果。
- 满足以下任一条件时，3D 场景替换为预渲染静帧：系统开启「减少动态效果」、浏览器不支持 WebGL 2、性能监测持续低于可用帧率。

## 7. 错误处理

| 情况 | 处理 |
|---|---|
| 词包加载失败 | 显示「词库加载失败」，提供重试按钮；已加载的进度不受影响 |
| `localStorage` 不可用或已满 | 提示进度无法保存，建议导出进度 |
| 导入文件格式不对或版本过新 | 拒绝导入并说明原因，当前进度不变 |
| 口令错误 | 抖动并提示「口令不对」，不透露更多信息 |
| 某个密文文件下载或解密失败 | 该项显示为占位，其余内容照常显示 |
| 3D 模型加载失败 | 降级为预渲染静帧 |

## 8. 测试

- **单元测试（Vitest）**：每日选词（到期优先、顺延、凌晨 4 点分界）、复习间隔计算、干扰项挑选（同词性、不重复）、进度导入校验和版本迁移。
- **加密测试**：脚本加密后，按浏览器的流程解密能还原原文；错误口令必然解密失败；输出的照片不含 EXIF；更换口令后仍能解密。
- **手动验收**：按第 1 节的五条完成标准，分别在手机和电脑上走一遍。

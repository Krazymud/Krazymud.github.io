# Midnight Garage：答错后手动进入下一词

日期：2026-10-13
状态：待审阅

上级文档：`docs/superpowers/plans/2026-10-09-midnight-garage-plan-1-trial.md` 里「答错后 1500 ms 自动下一题；答对后 4000 ms 不评级则默认还行」。本文只改这两条时机，评分规则和进度存储不变。

## 1. 范围

背单词界面在答错后停住，等用户自己进入下一词；答对后的自动提交从 4 秒改为 5 秒。

1. 点错选项后，选项锁定并揭晓正确答案，下面出现「下一题」。点这个按钮，或按回车，才把该词记为 `again` 并进入下一词。
2. 不点就停在当前词，没有任何倒计时。
3. 点对选项后仍显示「还行 / 会了」。5 秒内不点，按「还行」（`ok`）提交。
4. 每个词的间隔、到期日、当天进度和每日统计仍写入 `midnight-garage/progress`，格式不改。

**不做：** 答错后改选；答对后取消自动提交；改 `again` / `ok` / `good` 的间隔算法；改进度文件的结构或存储键；保险库的笔记和清单编辑（另写规格）。

## 2. 行为

揭晓规则沿用 `QuestionCard`：一旦选中，选项按钮禁用；正确项高亮，点错的那项划掉，其余变淡。中译英在揭晓后才显示英文单词和发音。

答错时，评分条的位置换成一颗全宽按钮，文案为「下一题」，样式与「会了」相同（`border-accent-hi`、`bg-accent/30`、加粗）。它和窗口级回车都调用现有的 `commit('again')`。数字键只在尚未作答时选题，答错后不再响应。答对后回车不提交，避免把「下一题」的快捷键用到评分上。

答对时 `GradeBar` 不变，只是倒计时时长改为 5 秒。倒计时走完仍提交 `ok`；用户点「还行」或「会了」则立即提交对应等级。

同一题只提交一次，沿用 `committedCursor`：连点按钮、按住回车，或按钮与回车各触发一次，都只记一笔。

## 3. 实现

只改 `src/trial/TrialScreen.tsx` 和它的测试。不新开组件，不改 `GradeBar`、`QuestionCard`、`engine` 或 `progress/store`。

- `GRADE_TIMEOUT_MS` 改为 `5000`。
- 删除 `WRONG_DELAY_MS`。
- 自动提交的计时器只在答对时启动，时间用 `GRADE_TIMEOUT_MS`，到点调用 `commit('ok')`。
- `picked !== null && !correct` 时，在 `QuestionCard` 下方渲染「下一题」按钮。
- 回车监听与现有数字键监听分开：仅在答错且题目仍显示时，`Enter` 调用 `commit('again')`。不自动聚焦按钮；和数字键一样听 `window` 的 `keydown`。

`commit` 仍负责记分、清空 `picked` 并前进。进度的读写路径不变。

## 4. 测试

改 `src/trial/TrialScreen.test.tsx` 里受时机影响的用例，并补一条回车用例：

- 答对后出现「还行」。前进 4999 毫秒仍停在当前词；再前进到满 5000 毫秒进入下一词，该词 `lastResult` 为 `ok`。
- 答错后不出现「会了」。前进 5000 毫秒仍停在当前词。点「下一题」后进入下一词，该词 `lastResult` 为 `again`、`interval` 为 1。最后一词答错也走同一条 `commit('again')`，点「下一题」后出现圈速总结。
- 「打开已完成的一圈时不再播放引擎声」改为逐题点「下一题」走完，不再靠计时器。
- 答错后按回车与点「下一题」效果相同。
- 答对后按回车不提交，评分条仍在。
